# SpellCheck v0.2.7

The focus of this release is a **stable and predictable core workflow** (select text → ⌥L → choose a prompt → the text is replaced), plus a model picker for the backup model and prompt caching for Mistral.

## New

- **The backup model now has the same experience as the primary model**: "Fetch models" fetches the model list for the backup field too, so you can pick from the list instead of typing the ID by hand. Manual entry still works, and fetching never overwrites what you have already saved. Fallback behavior is unchanged: the same request is retried once on the backup model for temporary failures; the document write-back is never repeated.
- **Prompt caching towards Mistral**: when the API URL points at Mistral, the app now sends a stable `prompt_cache_key` (only an anonymous numeric "fingerprint" of the shared prompt + selected prompt — no API key, text or prompt contents). This increases the chance that the repeated instruction prefix is reused from cache: cached input tokens are billed at 10% of the normal price. Note: hits are **not guaranteed**, the block size is 64 tokens, and short prompts rarely or never hit — so it is normal that not every request shows cached input in Admin/Usage. Other providers (OpenAI, DeepSeek, GLM, OpenRouter, local servers) get an unchanged request — nothing provider-specific is sent where it is not supported. Whether this actually produces measurable cache hits on your account is not yet verified — check Admin → Usage.

## Fixed / more stable (the intermittent problems)

An investigation of the whole chain (hotkey, menu item, text capture, picker, API call, target validation, focus handling, insertion) found three real weaknesses that match what you experienced ("nothing happens", "suddenly corrected later", "focus jumped back"):

- **Fast response to ⌥L and the menu item**: text capture via Accessibility is now time-bounded (0.75 s per call, 3 s total). Previously a slow app (e.g. Notion) could block capture for many seconds, making the picker appear to do nothing. If capture does not finish in time, you now get an error message instead of silence.
- **No duplicated/overlapping pickers**: repeated ⌥L presses or menu clicks while capture is running could previously open two pickers (the first one "leaked" with its mouse monitor still active). The session is now guarded synchronously, and every close path (choose, Esc, X, click outside, error) cleans up after itself — the picker can no longer sit "invisibly active" and block the next attempt.
- **No silent discarding of new edits**: if you choose a prompt while a correction is already running, the new one is **not** started (no duplicate requests, no extra write-back), but you are told in the menu bar ("A correction is still running…") instead of it disappearing silently. This was a likely cause of the text being "suddenly" corrected later: an earlier call was in progress the whole time, while new presses were dropped without notice.
- **Protection against stale operations**: before the text is written back, the app now also validates that the document's content is unchanged since capture. If you edited or moved away in the meantime (e.g. started typing in the Notion chat), the write-back is aborted and nothing is written to the wrong place. As before, focus is returned to the target app as part of the **requested** workflow — but a late response can no longer write text somewhere the user has already left.

Diagnostics (which capture layer was used, timings, abort reasons) are now logged internally — without API keys, prompts, text or API responses.

## Verification that remains (your test on a real Mac)

Automated tests (Core 76, Engine 49, App tests on macOS CI) and build/CI are green, but the following needs your confirmation in practice: ⌥L and "Open Prompt Picker" respond every time (also in Notion), no late/"ghost" corrections, no focus stealing while typing in the chat, backup model selection via Fetch models, and (if you want) cached tokens in Mistral Admin → Usage. GLM 5.3 / Flash is still supported — older error reports about decoding have been fixed.

## Installation

1. Download `SpellCheck-macOS.zip` and unpack it.
2. Move SpellCheck.app to the Applications folder. Alternatively: run "Check for Updates…" in the menu-bar app from v0.2.1+.
3. The app is ad-hoc signed: the first time, macOS may ask for confirmation — right-click → Open. After an update, Accessibility permission (System Settings → Privacy & Security → Accessibility) may need to be re-enabled.
