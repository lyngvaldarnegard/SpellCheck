# SpellCheck v0.2.8

Three useful improvements from your feedback — the core workflow (select text → ⌥L → choose a prompt → the text is replaced) is unchanged.

## New

- **Spinner at the mouse pointer while the AI is working (like FixKey)**: as soon as you choose a prompt, a small dark spinner with a circular animation appears just above the mouse pointer, until the correction completes. It signals that the text has been sent and the AI is working. The spinner is non-interactive: it does not steal focus, does not intercept clicks (clicks pass straight through) and does not affect the keyboard.
- **Identical text is replaced too**: if the AI returns exactly the text you selected (nothing to fix), it is now written back anyway — the visible replacement is your confirmation that the workflow actually ran. Previously the write-back was skipped, which could look like nothing happened. The app still verifies the document; for identical text an unchanged document is precisely the expected outcome and counts as success.
- **Less window nuisance during the whole workflow**: SpellCheck's own windows (Settings, Prompt Editor) are now kept behind all other apps' windows until the correction finishes — not only while the picker is open. None of our windows should jump forward while a correction is in progress. (If you still see windows come forward at ⌥L, report it in issue #12 — it has not been reproduced on the development side.)

## Verification that remains (your test on a real Mac)

Automated tests (Core 76, Engine 49, App tests on macOS CI) and build/CI are green. The following needs your confirmation: the spinner appears at the mouse pointer and disappears when the correction completes; identical text is visibly "replaced"; and no SpellCheck windows come forward at ⌥L or during a running correction.

## Installation

1. Download `SpellCheck-macOS.zip` and unpack it.
2. Move SpellCheck.app to the Applications folder. Alternatively: run "Check for Updates…" in the menu-bar app from v0.2.1+.
3. The app is ad-hoc signed: the first time, macOS may ask for confirmation — right-click → Open. After an update, Accessibility permission (System Settings → Privacy & Security → Accessibility) may need to be re-enabled.
